# Markdownからの図解生成E2Eシナリオ

状態：**未実施**。この追加は実行可能な検証手順と入力資料の整備であり、実際の自然言語生成・再レンダリング・保存を検証済みとはしない。

## 依頼
新しいCodexセッションで次を入力する。JSONを事前に渡さない。

```text
AGENTS.mdを読み、examples/agent-creation/input.mdを図解して。
図解タイプと描画手段は内容に合わせて選んでください。
対応可能な全形式をローカルに保存し、検証記録を付けてください。
```

## 手順と期待結果
1. Markdownを直接読み、目的・読者・必須項目と未指定事項を整理する。説明用仮定を保持する。
2. Agent Creation Modeを選択する。判断と修正ループが中心なのでFlowchartが適切。共通ルールとFlowchartテンプレートを読み、固定Roadmapへの変換を避ける。
3. 準備、確認、記載充足の判断、修正、承認済みローカル保存、終了にIDを付ける。「すべて記載」「不足あり」の分岐と修正から確認への戻りを記録する。必須項目一覧と未指定事項を注記へ対応付ける。
4. 利用可能なSVG・HTML等の手段を選び、選択理由と形式別能力を記録する。共通設計と描画ソースを保持し、対応形式を生成する。利用不能なPDF/PPTX等は理由付きで未対応とする。
5. 再レンダリングし、全体と100%表示で日本語、判断内の文字、矢印ラベル、戻り線、余白、はみ出しを確認する。入力対応と全関係を照合し、不合格なら修正・再検証する。
6. rules/storage.mdのID・版パッケージへ保存し、原資料参照とハッシュ、共通設計、描画ソース、成果物、validation.json、形式別状態・サイズ・SHA256を残す。2.0 metadataを使う場合はスキーマ・意味・集約検査も行う。
7. ファイルを再度開き、ハッシュと内容を照合する。成果物へのリンク、検証結果、未対応・未検証事項、S3未送信を報告する。AWSアクセスは不要。

## 合格基準と実施記録
- 内容：目的・読者・必須項目・条件・仮定が保持され、期間やシステムを創作していない。
- 手段：分岐と戻りを保持し、既存エンジンの範囲外を理由に生成を中止していない。
- 品質：rules/quality.mdと形式別検査の証跡があり、数値検査と目視を区別する。
- 保存：再生成可能なローカル記録、実ファイルの整合性、形式別状態が残る。未検証をverified/completeにしない。

実施時にはこの例の隣に実施記録を追加する。日時、実行環境、実際のユーザープロンプト、読取範囲、モード・手段、出力先ID・版、コマンド・ツール、入力対応表、関係一覧、再レンダリング画像と目視結果、形式別状態、ハッシュ検査、修正履歴、未検証事項を記載する。

別の補助経路検査として既存Linux例のJSONをCLIで生成し、既存回帰テストを実行できる。ただし、それを本シナリオの自然言語意味理解・独自描画の合格証跡にはしない。
