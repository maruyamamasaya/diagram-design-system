# 図解・プレゼン共通アイコン集

人物、もの、端末、サーバー等の汎用記号と、AWS/Azureの公式サービス記号をローカルに保持する。制作時はまず [catalog.json](catalog.json) の `label` / `keywords` / `id` で探す。[一覧](index.html)はブラウザーで開ける。素材の使用は任意で、関係・説明の理解に役立つ場所へ名称とともに置く。

## 選び方

- サービス未指定の人・PC・サーバー・文書・建物・物品には `generic.*`（Lucide）を使う。1図内で線画の系列を統一する。
- AWS/Azureの特定サービスには `aws.*` / `azure.*` を使う。汎用クラウドに特定ベンダーの記号を使わない。似たサービスを誤った公式アイコンで代用しない。
- 名称、境界、矢印、操作ラベルを先に設計し、各要素を識別しやすくするために追加する。空白を埋める装飾には使わない。
- 寸法・線幅・配色・名称併記の正本は [design](../../rules/design.md)。公式図柄の原色・縦横比を保ち、反転・回転・切抜き・形状変更をしない。ブランドロゴとしての転用は利用条件を別途確認する。

## 制作パッケージへの受け渡し

1. catalogで意味と対象サービスを確認し、ファイルのSHA256を照合する。
2. 使用ファイルを制作パッケージの `source/assets/` 等へコピーする。共通集への絶対パス参照や `../` 参照を完成パッケージへ残さない。
3. 使用したid、出典、版、利用条件、元SHA256、パッケージ内パスを素材台帳へ記録する。Lucide使用時は `lucide/LICENSE` と `lucide/LICENSE.feather` も同梱する。
4. SVGは独立一枚図・対応する専用描画経路で使える。登録グラフィックのassetsは現在PNG/JPEGのみなので、SVGを縦横比・原色を保ってPNGへ変換し、変換後SHA256と元idを記録する。SVGをそのまま入力して対応済みと扱わない。
5. 登録レイアウトのアイコンスロットは新設していない。対応スロットや専用固定登録を使い、通常v2へ任意座標を追加しない。最終PNG/PDF/PPTXで大きさ・ラベル・関係を確認する。

## 出典・利用条件

- Lucideは0.468.0に固定。ISCと継承部分のMIT許諾表示を同梱。各SVGは当該タグの原本。現行最新版であるという意味ではない。
- [AWS Architecture Icons](https://aws.amazon.com/architecture/icons/)：2026-07-31配布物。図解・プレゼン等での利用案内を2026-10-21に確認。既存制作物の公式配布原本から再利用し、配布ZIP内の元パスとSHA256を台帳へ保持する。
- [Azure Architecture Icons](https://learn.microsoft.com/en-us/azure/architecture/icons/)：公式配布V24。構成図・研修資料・文書での利用許諾を2026-10-21に確認。図柄変更・反転・回転・切抜きを行わず製品名を併記する。Microsoftは他の権利を留保する。

公式素材は自由利用ライセンスではなく各社の許諾範囲で使う。取得URL・取得時の条件要約・配布版・配布ZIPのハッシュは [sources.json](sources.json) に保持。再配布用の汎用アイコン商品としての利用を想定しない。

## 追加・更新

必要な記号がなければ公式配布または利用条件を確認した同一系列から追加する。SVG/PNG、SHA256、名称、用途、出典、版、条件を揃えてcatalogへ登録し、一覧を更新する。最新版への自動追従はしない。旧制作パッケージの素材は書き換えない。図柄は取得版のもので、過去の出来事の当時のデザインを証明しない。
