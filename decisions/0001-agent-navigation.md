# AI作業の入口と責務分離

日付：2026-10-09。状態：採用。

## Context
資料作成・システム改修・文書更新で同じ入力を使う。既存生成規則と開発探索規則を混ぜると、資料中の記述を実装指示と誤認し、不要な変更や大量読込につながる。

## Decision
ルートAGENTSで依頼の種類と変更範囲を判断し、CURRENTから必要な正本・CODEMAP・検索・対象の子AGENTS・テストへ進む。viewer、S3保存、プレゼンだけに子AGENTSを置く。検証は依存追加なしの既存コマンド集約と文書導線チェックを使用する。

## Reason
異なる技術・テスト・外部書込・描画契約の境界だけを階層化し、共通の品質・承認規則を維持する。入力内容だけでは改修を開始しない。

## Alternatives
全規則をルートへ集約すると常時読込が増える。全ディレクトリへのAGENTS配置は重複と鮮度管理負担が増える。Semantic Searchサービスの追加は現時点の規模に対して不要。

## Consequences
状態が変わった文書だけ更新し、履歴はsessionsへ記録する。検索索引や自動意味判定は提供しない。登録表とコードの不一致は描画認定とは分けて記録し、検証を伴わず状態を昇格しない。
