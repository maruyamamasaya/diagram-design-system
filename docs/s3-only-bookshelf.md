# 本棚のS3一本化（実機確認待ち）

2026-10-19本人指示。実機確認は後日とし、コード変更・自動テスト・配布候補ビルドまでを行う。

## 表示が違っていた理由

旧Mac版は登録した制作フォルダのmetadataを再帰探索し、iOSは認証API経由でS3の公開済みcatalogを読む。S3未送信の制作資料やローカルの新版もMacだけに表示される実装だった。今回Macも同じ認証付き `GET /v1/diagrams` を正本に切り替える。未公開の制作原本は本棚へ混ぜない。iOSは従来どおりプレゼン/図解を分け、Macもプレゼン資料/図解ライブラリを切り替えるため、比較時は種別・検索・タグをそろえる。iOSに保存した旧版を優先している場合は更新操作も必要。

## 今回の実装

- iOS：ローカル資料のタブ/本棚メニューと、サンプル/本番の利用者切替を廃止。製品の起動経路はS3認証本棚のみ。MockCloudAPIと旧ファイル読取コードは自動テスト用に保持し、製品ナビゲーションには出さない。過去のローカル原本/ブックマークは削除しない。
- Mac：登録フォルダ/保存場所の入口を廃止。通常起動はローカル探索/監視を開始せず、既存Mac Cognito接続でS3 APIを読む。明示したログイン操作だけブラウザ認証を開き、通常更新はsilent refresh。分離された `--state` / stateURL指定の既存回帰試験では旧スキャナを利用可能とする。
- 既存のフォルダ/タグ/まとめ設定を保持し、実際にS3一覧に存在する資料IDだけ表示する。通常一覧はS3最新版。Mac右側の版選択は今回取得した最新版だけで、旧制作フォルダの改訂履歴は取り込まない。S3旧版を選ぶUIの拡張は今回含めない。
- Macカードは正方形を維持し、標準最小幅160pt・スライダー120〜220ptへ小型化。カードはサムネイル＋2行予約/末尾省略のタイトルのみ。ページ数/版の表示は右のプレビューに集約する。
- 一覧は全ページ取得後に原子的に置換。重複ID/不正ID/巡回cursor/件数超過を拒否。表示中のカードは必要なPNGのみ取得し、選択時にPDFプレビューを取得。PNG/PDF/PPTXの明示取得も既存APIで行う。
- 端末内はアカウント別 `lifecycle-<hash>.copies/<id>/<version>/` の取得用キャッシュのみ。取得ファイルはHTTPSホスト、メソッド、有効期限、形式、名前、サイズ、SHA256を照合し、S3へAPI Bearerを送らない。リダイレクトを拒否し、応答サイズを制限する。壊れた/未照合のキャッシュをプレビューへ出さない。
- 共通の削除通知を保存後にID配下の全コピーを消す既存契約を再利用。遅い応答が削除/更新後に戻っても保存/表示しない。復元後はS3一覧を再取得する。

S3を正本とすることと、閲覧のために端末へファイルを一時取得することは両立する。Macは再起動後の一覧復元にオンライン取得を必要とし、iOSの既存の端末保存/オフライン閲覧は維持する。今回、Macの永続オフライン索引や旧版取得UIは追加しない。

## Mac取得待ちの修正（2026-10-19）

実画面でプレゼン選択後の「資料を取得中」と、その後の取得失敗を確認。S3のAsyncBytesをMainActor外で読み、表紙の同時準備を2件までに制限して選択資料が大量のAPI待ち枠の後ろへ並ばないようにした。PDFプレビューは表紙取得に依存させない。失敗時は取得中表示を終え、画面内の「再取得」でやり直せる。既存のホスト/リダイレクト/バイト数/SHA256検証と削除後保存拒否を維持する。診断ログはHTTP状態/バイト数/エラー型のみで、token・署名URL・資料本文を含めない。

2 MBのPDFを表紙取得なしで保存・SHA256照合する回帰を追加。Macの自動検証と、本番S3・実画面の確認結果は[作業記録](../sessions/2026-10-19-mac-fetch-and-prepush.md)で区別する。

### 再起動後の閲覧キャッシュ

認証済みの資料詳細（資料ID/版/一覧情報/許可ファイルのサイズ・SHA256）をアカウント別copies内のdetail.jsonへ保持する。再起動後も、取得済みのS3一覧と資料情報が一致し、サイズ/SHA256が一致したキャッシュだけを表示する。署名URLやtokenは保存しない。破損メタデータは無視して認証APIへ再照会し、破損ファイルは再取得する。一覧自体のオフライン索引は追加していない。

保持目安は512 MiB・直近30版。認証済み詳細のあるキャッシュ版を最終利用順で整理し、取得中の版は除外するため一時超過はあり得る。整理対象はアカウント別の閲覧コピーだけ。制作原本・整理設定・S3へは作用しない。資料削除通知時のコピー削除は引き続き優先する。

同期接続は既存ログインのsilent確認を先に行い、必要な場合だけ再ログインする。本棚取得と同じ接続のペーサーを共用し、複数の接続が独立にAPI要求枠を予約することを避ける。初回統合の確認、管理バックアップ、競合保護、手動同期の回数制限は維持する。
