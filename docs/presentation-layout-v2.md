# 登録レイアウトv2

v1の入力と描画を保持し、v2はtemplateIdで明示選択する。任意座標は追加しない。
寸法の機械可読な正本は[profile](../config/presentation-profile.json)。色・フォント・キャンバスは共通ルールを継承する。

|種類|用途と選択条件|配置・上限|超過時|
|---|---|---|---|
|Title|資料の主題・概要|大きい見出しと副題、囲いなし。既存文字数制限を保持|単一項目の超過は明示エラー|
|Bullet|短い同列要点、コマンド＋説明|全角コロン前を左ラベル、後を右説明。最大6項目。コロンなしは全幅。罫線で区切る|項目単位で分割、縮小しない|
|Two Column Comparison|同じ軸の2案|比較軸を左に一度だけ表示、2列＋横罫線。最大5軸|行単位で分割|
|Diagram|順序が中心の直列Roadmap|意味を持つノードのみ薄い面、接続矢印・ラベル。既存1〜4段階|ノード内超過はエラー、AIが意味を保って再構成|
|Table|行列が対応したデータ|見出し帯だけ面、本文は横罫線。2〜4列・最大8行|行単位で分割、見出し再掲|
|Summary|結論と次の行動|結論を番号・太字で階層化。行動だけ面。最大4項目|項目単位で分割、行動は最終ページ|

本文24、補足20を下回らない。見出し32、ページタイトル44、表紙56。行高は設定値と実グリフ高の大きい方。余白48、内余白16で共通検査を行う。登録された数値を各テンプレートに複製しない。schemaVersion 1.2は旧1.0/1.1を受理する追加変更。v1をv2へ自動移行しない。構成を変えた版はpresentationVersion/slideVersionを更新する。

情報密度は文字を増やすことと同義ではない。既存入力の条件・説明を保持し、重複する軸や囲いを減らす。Titleや短い結論では余白を意図的に残す。

検証：スキーマ、実グリフ、領域・包含・重なり、最小文字サイズ、PNGサイズ・モノクロを自動確認。enclosedGroups/enclosedAreaRatioは比較指標で、少なければ良いという合否基準ではない。余白、単調さ、意味のまとまり、見出し階層、内容欠落は全ページの目視と原文照合で確認する。未認定テンプレートは通常生成で拒否する。開発用内部APIのallowUnreviewedTemplatesはローカルの認定作業だけに使い、CLIには公開しない。

スマホでは横向き・ズームを前提とする。1600幅の図を844幅で全体表示すると本文24は約12.7画面px、補足20は約10.6pxになる。細部は1.5〜2倍程度のズームで確認する。実機・プロジェクターの見え方は別検証とする。

## 役割に応じた固定列幅（2026-10-19追加）

Tableの任意項目widthProfileで選択する。省略またはbalancedは従来の等幅。label-detailは2列、label-detail-conditionは3列、label-detail-example-conditionは4列。短い項目名の列を狭くし、説明・具体例・条件へ幅を割く。比率の正本はconfig/presentation-profile.jsonのtableWidthProfiles。列数不一致と任意数値の幅指定は拒否する。各列の意味は列名とセル内容で表し、名前だけで内容を自動生成しない。

実測した各列の文字高で行高を決め、行単位で分割し見出しとプロファイルを再掲する。PDFとPPTXはSVGの確定した列境界を使用する。既存v1/v2の等幅入力とIDは保持。選択方針と専用グラフィック版の仕様カタログは[レイアウト方針](presentation-layout-policy.md)。

選択例（Tableのcontent。説明用サンプル）：

```json
{
  "heading": "原資料の条件を成果物まで保持する",
  "widthProfile": "label-detail-condition",
  "columns": ["工程", "実施すること", "成立条件・注意点"],
  "rows": [
    ["構成", "原資料の主張と根拠をページへ対応づける", "未確認の事項を事実として補完しない"],
    ["検証", "実描画と形式の再読込で文字・関係を確認する", "自動検査と目視を分けて記録する"]
  ]
}
```

今回の固定列幅の実描画・PDF/PPTX変換・目視の範囲は[検証記録](../sessions/2026-10-19-document-routes-layout-update.md)を参照。全入力・全端末の認定ではない。
