# プレゼンの表現モードとグラフィック版の運用

表現モードの選択は[presentationプロンプト](../prompts/presentation.md)を正とする。未指定の新規制作で確認が必要な条件と、明示された制作条件から専用登録経路を選べる条件は同プロンプトに従う。生成モード、保存承認とは別の選択。

## 制作手順

1. 原資料の読取範囲と重要事項を記録し、主張・根拠・例・留保を分ける。文献調査を伴う依頼では原典・研究文献の該当箇所をたどり、ページと出典を対応させる。
2. ページごとに説明したい関係を決める。因果、部分と全体、比較、同じ対象の異なる見方、時間の順序を混同しない。図の矢印の意味を記録する。重要な留保はページに表示し、ノートへ隠さない。
3. グラフィック版では、関係を説明する編集可能な図、同じ軸の比較表、具体例を理解するイラストを選ぶ。全ページを画像化しない。枚数と密度は[layout](../rules/layout.md)を基本とし、画像数は説明の必要性で決める。説明に役立つ新規イラストはimagegenスキルで生成し、実際のプロンプトと原画像をローカル保存する。生成画像を史料・写真記録・科学的証拠として扱わない。
4. 共通ルールの白背景・モノクロを土台とし、[design](../rules/design.md)に従って公式アイコンと必要な補助色を使う。文字階層・整列・余白を守る。システム登録v2で表現できるものは既存経路を使う。不足するレイアウトは制作パッケージ内の登録表・固定配置仕様・意味入力契約を先に作り、任意座標の入力を禁止する。サンプルを実描画して検証・目視し、その資料に限定した認定後に使う。システムの登録簿・能力を変更したとは報告しない。
5. 共通配置からPNG/PDF/PPTXを生成する。PPTXの文字・関係図は可能な範囲でネイティブ要素にし、イラストが画像であること、書体依存・編集上の制約を明示する。
6. [quality](../rules/quality.md)に沿い、入力対応、文字境界・重なり、寸法・配色方針と公式アイコンの原色保持、形式間の文字欠落を確認する。最終PDFとPPTXを読み込み直して再描画し、全ページ一覧を目視。問題箇所を修正して影響範囲を再確認する。PowerPoint本体と代替レンダラーの検証を区別する。
7. 原資料、意味入力、登録表、配置仕様、描画・変換手段、生成画像とプロンプト、依存ハッシュ、成果物、検証記録をローカルに保存する。画像数やページ数だけで品質を保証しない。

## 対応境界と保存

現在のシステム登録エンジンは任意イラスト組込み・任意関係図を自動処理しない。グラフィック版はCodexによる構成・専用登録・描画検査を含む制作運用であり、新しいCLI機能や全資料での品質保証ではない。パッケージ専用契約を標準presentation.schema.jsonへ適合したと偽らない。

標準経路の一括制作は[Phase 12](phase12-workflow.md)。専用パッケージのS3保存では[保存仕様](s3-storage.md)に準拠したPDF/PPTX/ページPNGと最小manifestだけを送る。通常upload CLIが専用契約を受理するとは扱わない。入力検査・検証証跡・ハッシュを確認する個別引渡しをローカルに記録し、既存S3Storageの非公開preflight・サイズ上限・保持上限・条件付きPUT・全GET照合・catalog最後掲載を維持する。保存先と資料送信の明示承認は引き続き必要。承認が追加で必要と判断された場合は、確定したバケット・対象ファイル・合計容量を示して確認し、回答まで送信しない。

## 確認した実例

2026-10-10「色即是空・空即是色」深掘り版：24ページ、生成イラスト4点、6種類の専用固定レイアウト。PDF/PPTX/PNG、全表示文字の欠落0、全ページ再描画・一覧目視を確認。PPTXは文字・図形をネイティブ出力し、生成イラストは画像。書体非埋込、PowerPoint本体表示は未検証。[制作記録](../sessions/2026-10-10-emptiness-deep-presentation.md)。この実例の認定を別資料の自動合格に流用しない。
