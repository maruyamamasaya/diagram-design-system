# 資料取得障害の修復：AWS適用前の変更案

2026-10-20 JST。本人の明示承認後に適用済み。本人認証 `/v1/me` は200、一覧とlifecycleは409 INVALID_MANIFESTを実測。S3 catalog64件のうち新形式63件は修正後の検査ですべて合格。美術史v3の `slides/slide-NNN/slide.png` と43,829,069 bytes PDF/30,136,175 bytes PPTXの限定承認が本番コードに未反映。1資料の拒否でcatalog利用API全体が停止している。

## 変更対象

東京の既存stack `diagram-library-api` のLambdaコードだけを更新。修復コードを既存専用bucketの `deployments/api/<SHA256>.zip` へAES256/条件付きPUTし、GET/SHA256照合後、live templateのCodeKey既定値/CodeKeyパラメーターだけを変更してCloudFormationで適用する。既存パラメーターはUsePreviousValue。変更セットでFunction Code以外の実質変更があれば停止する。

- 登録済みパス形式2種類を厳格に許可し、数値ページ重複/欠番/パストラバーサルを拒否。
- 承認済み美術史v3をID/版/保存先/全対象サイズ/SHA256へ固定して許可。他資料の上限を拡張しない。
- 追加依頼による再発防止：保存/閲覧の検証器を共有し、不正な1版を警告付きで隔離。`GET /v1/reader-contract` はデータを含まない仕様fingerprintのみを公開し、保存前に本番一致を必須確認する。既存の資料APIの認証は維持する。追加リソース/IAM変更なし、同じコード更新/試算枠内。
- 既存owner/JWT/暗号化/短期URL/ゴミ箱/整理同期/容量/請求flagを維持。
- API毎秒1要求/瞬間5要求、Lambda nodejs22/256MB/20秒、ログ14日を維持。IAM、バケット設定、Cognito、予算、新規リソースは変更しない。
- 10GBキャッシュは端末内の変更で、S3の保存容量追加はない。
