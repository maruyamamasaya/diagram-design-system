# iOS連携方針

iOSプロジェクトの現在の配置は `Development/zukan`（旧名：Presentation-Viewer）。現行の操作・実装状況は [zukan README](../../zukan/README.md) と [CURRENT](../../zukan/CURRENT.md)、整理同期は[実端末の接続状況](organization-sync-live-clients.md)を参照する。以下は2026-10-09時点の設計案であり、未実装・未接続という記述は当時の状態を示す。

## 推奨
既存zukanを閲覧クライアントとして拡張し、このプロジェクトは生成・保存・共通API・Webを担当する。リポジトリを分離したままAPI契約で連携する。別iOSアプリの新設は現時点では勧めない。

既存アプリはローカル/iCloudフォルダのSVG・PNG・PDF・PPTX閲覧、ピンチ・パン、PDFプレゼンと外部表示を持つ。一方、独自ネットワークAPI・認証・クラウドキャッシュはない。図解一覧と安全な取得を追加すれば既存表示機能を再利用できる。既存アプリのREADMEとソースを2026-10-09に確認した設計案であり、iOS実装・ビルドは今回行っていない。

## 連携の順序
1. Web/APIをHTTPSで公開し、OIDC認証と単一ユーザー認可を整える。現在のloopback専用パスワード認証を公開・iOS本番利用しない。
2. 既存iOSへローカル資料と独立した「図解ライブラリ」を追加する。OIDC authorization code + PKCE、トークンはKeychain。AWSキーを持たせない。
3. docs/viewer-api.mdの一覧・詳細・access-urlをURLSessionで利用する。共通ID・版・SHA256を維持し、期限切れURLは再認可して取得する。
4. 承認されたダウンロードをアプリ専用領域へ保存し、SHA256照合後に既存ビューアーで表示する。ID/版/形式でキャッシュを区別し、サイズ上限・明示削除・ログアウト時の保管方針を設計する。既存の元資料を直接参照する機能は維持する。
5. Macでビルド・XCTest、実機で認証・失効・オフライン・横画面・外部表示を検証する。

S3は非公開、署名URLは短期でログに残さない。署名URLは永続キャッシュしない。現v1 APIはSVG/PNGが対象。PDF/PPTXのクラウド提供はエンジン・メタデータ・API対応後に追加する。

## 別アプリを選ぶ条件
図解専用の編集・生成・アップロードが中心になる、利用者や配布先が既存プレゼンアプリと異なる、独立した製品として公開する場合は別アプリを検討する。その場合も共通APIとSwiftの表示・APIクライアント部品を共有し、認証・保存仕様を二重化しない。
