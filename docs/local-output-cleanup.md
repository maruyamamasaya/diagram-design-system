# ローカル成果物の整理

保存と不変性の正本は[保存ルール](../rules/storage.md)。本書はoutputs/内の整理手順を定める。.gitignoreは追跡対象を制御するだけで、バックアップや削除可否の保証ではない。S3の完成版保存だけでは再生成用入力を復元できない。

## 制作完了時の標準運用

2026-10-23本人指定。今後は音楽史を含む資料制作・改訂ごとに、必要な出力と内容・形式・目視の検証を終えてから、本書の手順で不要な内部SVG・中間ファイルを整理し、結果を納品報告へ含める。この範囲のローカル整理は都度の追加依頼を待たず実施する。CLI全経路に自動削除機能があるという意味ではなく、エージェントが制作の終了工程として実施する。

- プレゼンの内部SVGは描画・形式変換・検証中に使い、完成版と再生成入力・コード・素材・フォントを確認後、不要と確認できたものを削除する。PPTXが存在するだけでは削除条件を満たさない。
- 候補PDF/PPTX、試作・再描画画像、重複ファイル等も、完成版との対応・必須参照・検証証跡を確認してから整理する。確認用画像には下記の一覧・代表画像・索引の保持条件を適用する。
- SVG指定の納品物、素材・アイコン、独立一枚図の描画ソース、旧単一図解契約で必須のSVG、別資料や再生成処理が入力として読むSVGは保持する。未完成・失敗・用途不明の出力は保持理由を記録する。
- 旧版は版番号や古さだけで一括削除しない。不変metadata・manifestは書き換えず、契約上省略可能なSVGの削除を別記録に残す。契約が現存を要求するファイルは削除しない。
- 最終報告には削除件数・論理バイト数・保持対象の確認結果・保留項目を記載する。S3送信・削除やAWS変更の承認へは拡張しない。

## 残すもの

- 完成版、契約に含まれるページPNG・サムネイル、metadata・manifest・validationとその参照先。
- 原資料、構成JSON、登録定義、描画・変換スクリプトと依存コード、再生成で読むscenes、素材・素材台帳・由来・ライセンス・生成プロンプト。
- 使用したフォントの実体、版・SHA256・ライセンス。実行環境と依存ロック、再実行手順。
- 作業中・未完成・用途不明のファイル、実行中の出力とロック。

build/という名前、完成PDFの存在、最上位metadataの不在だけで削除しない。一枚図の原画像も中間物とは限らない。既存契約のSVG省略例外を他のファイルへ拡張しない。

## 整理の手順

1. 対象パッケージ単位で完成版・入力・派生物・検証証跡を分類する。metadata、package-manifest、validation、保存manifest、素材の再利用先を含む参照を確認する。パッケージ外の依存も調べ、不明なら保持する。
2. 完成版と必要な再生成入力の存在・ハッシュ、参照解決、必要なフォントの読み込みを確認する。再生成を試す場合は別の作業先を使う。完全な再出力をしていなければその限界を記録する。
3. 削除候補を明示した計画に、パス・サイズ・SHA256・判断根拠・保持先を記録する。同一ファイルの重複は完成版とのSHA256一致が必要。名前がcandidate/normalizedでも一致しなければ残す。必須参照のある複製は削除しない。
4. PDF等から作った確認画像は、元の完成版が有効で再描画でき、必須参照がない場合に限り候補にする。削除前に全ページの一覧画像、代表ページ、元ファイルと画像のハッシュ・寸法を含む索引を残す。テスト出力も必要な検証結果を小さな記録に残す。
5. 削除直前に対象一覧とハッシュ、稼働状況を再照合する。シンボリックリンクや想定外の追加ファイルがあれば中止する。広域globではなく計画に載せたファイルだけを削除する。
6. 削除後に完成版・入力・manifest等の保護対象のハッシュを再照合し、削除一覧・論理バイト数・残した証跡・未検証事項を記録する。論理サイズを実際の空き容量増加と同一視しない。AWSの削除・設定変更は別工程とする。

## 期限付きフォント参照の修復

/tmp等を再生成の依存先にしない。同じ書体名だけで置き換えず、既存記録と同じSHA256の実体を永続作業領域へ保存する。検証記録がスクリプトのハッシュを保持している場合、完成済みの原スクリプトやmanifestを書き換えず、別の再生成作業先へ入力と必要素材をコピーして参照・出力先を修正する。修復前後のハッシュと依存を記録する。

この作業先は旧版を公開し直すパッケージではない。入力や依存を変更した成果物を公開する際は、新しい版で通常の検証とmanifest作成を行う。
