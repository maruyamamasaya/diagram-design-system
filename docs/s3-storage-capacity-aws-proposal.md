# S3容量取得：AWS適用承認案

2026-10-19、ap-northeast-1。本人承認後に適用済み。本書は承認時の構成/試算。実配備zipは922,284 bytes、確認は公開API11要求（基準4＋適用後7）とS3読取で、承認時の想定内。[結果](s3-storage-capacity.md#本番反映2026-10-19)。

## 対象

既存diagram-library-apiのLambdaコードを更新し、環境変数 `VIEWER_STORAGE_CAPACITY_ENABLED=true` を追加。既存roleに専用bucket限定 `s3:ListBucketVersions` を追加する。[権限JSON](../infra/storage-capacity-policy.proposed.json)。この権限はキー/サイズの一覧取得だけで、データの読取・書込・削除権限を追加しない。既存role全体の権限は維持する。ローカル短期roleセッションでも同フラグ時のみ追加許可するが、role元の権限にない場合は取得不能とする。

新bundleを既存配備先へ不変キーで保存する。既存HTTP APIのproxy routeを利用し、Cognito本人認可、256MB/20秒、ログ14日、暗号化/公開ブロック/バージョニング/既存予算を維持。新課金サービスや定期監視は追加しない。iOS端末更新は本番API照合成功後とする。資料データの変更はしない。

## 料金シミュレーション

固定費増分0円。料金参照は本日取得済みの[公式東京単価/SKU](shared-trash-aws-rates.json)を使用し、公式[S3](https://aws.amazon.com/s3/pricing/)、[API Gateway](https://aws.amazon.com/api-gateway/pricing/)、[Lambda](https://aws.amazon.com/lambda/pricing/)ページを2026-10-19に再確認。為替150円/USD・税10%は仮定。S3 LIST 0.0047 USD/1000回、HTTP API 1.29 USD/100万回、Lambda 0.20 USD/100万回・0.0000166667 USD/GB秒、ログ取込0.76 USD/GiB・保持0.033 USD/GiB月、インターネット転送0.114 USD/GiB。

現状851版で1集計につきLIST 1回。2端末が別々に取得しサーバーキャッシュが効かない保守条件。1取得=API1回、Lambda 256MB×2秒、LIST1回、ログ1KiB取込/14日保持、応答1KiB。バックグラウンド取得なし。取得60秒内のキャッシュは削減として計上しない。

|月30日の条件|取得/API/LIST数|転送無料枠あり|転送無料枠なし|
|---|---:|---:|---:|
|通常：各端末1回/日|60|0.15円|0.16円|
|多用：各端末20回/日|1200|3.03円|3.05円|
|多用＋全取得3回試行|3600|9.07円|9.14円|

上表はAPI/Lambda/S3/ログの無料枠・クレジットを全て除外。転送枠だけを分岐。全無料枠が残る場合はさらに低いが0円を保証しない。計算は `N × (0.00000129 + 0.0000002 + 0.25×2×0.0000166667 + 0.0000047 + 1024/2^30×(0.76+0.033×14/30) [+1024/2^30×0.114]) ×150×1.1`。

既存owner1 MAUを再利用し追加MAU0。認証トークンは既存フローから取得し、容量APIで新しい認証サービス呼出しを行わない。既存owner費用を別途配賦する場合の参考は0.015 USD×165=2.48円/月（既存費用）。現在のbucket保存費約2.28円/月、既存同期/閲覧/転送等は別で、上表は増分のみ。アカウント全体の実請求額を断定しない。

配備時の一時費用はコード5MiBを旧版保持で1か月保存＋PUT1回＋確認20API（各20秒、LIST最大100回、ログ100KiB）でも約0.50円を目安とする。実際のbundleサイズとリクエスト数を適用前に確定する。既存bucketの容量はbundle保存後にわずかに増える。

版数増加でLIST回数が増える。10万版/100ページなら多用1200取得のLISTだけで約93.1円/月となり既存費用込み100円超の可能性がある。上限/時間切れでは部分結果を出さない。更新頻度を落とすか、日次Storage Metrics方式を別途評価する。通知やキャッシュを課金上限保証にしない。

## 適用と確認

既存構成を再読取→差分確認→コード/IAM/環境更新→認証付きGETとCLIの容量照合、未認証拒否・旧一覧/整理同期/ゴミ箱の読取回帰→成功後iOS更新。失敗ならフラグ無効化/旧コード復帰を選び状況を報告する。実資料の書込・削除で検証しない。

承認対象は上記コードasset保存、既存APIコード/role/フラグ更新、読取検証、成功後iOS端末更新。[AGENTS](../AGENTS.md)の「具体的な構成と料金を示して明示承認を得るまで行わない」に従い、本人の明示承認後に適用した。
