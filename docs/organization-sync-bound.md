# 通常本棚の整理情報同期：テスト接続

2026-10-17。[同期画面](organization-sync-ui.md)に、明示的なTestLibrarySyncBindingを渡せるようにした。既定は従来の検証コピーで、普段使っている本棚やAWSへは有効化していない。今回の適用・操作対象は/tmpの合成Mac本棚と使い捨てSimulatorだけ。

## 動作

通常画面のフォルダ作成/変更/並べ替え/解除、所属変更、グループ/タグ、まとめの保存を同期対象へ投影する。初回は既存の確認画面で統合案を選択し確定する。その後の通常保存では前回観測した本棚との差分だけを永続送信待ちへ積む。存在しない設定を初回から削除と推測しない。再起動後、同期画面を開いて手動同期したときも実ファイルの差分を再確認する。常時接続・バックグラウンド同期・自動pollは追加していない。

送信前にチェックポイントを保存し、受信後にも適用前の結果と反映予定の投影を保存する。反映直後に中断しても、受信内容を新たな通常編集と誤認して未解決の競合を消さない。通常保存が通信中に完了した場合は再投影してから反映する。同期中の新しい通常編集要求は保存前に拒否する。競合提案はチェックポイントへ保持し、通常本棚にはサーバー状態を表示する。解決案を選んだ後は再度「今すぐ同期・再試行」で本棚へ反映する。通信失敗は送信待ちを保持し、反映失敗は「本棚への反映待ち」として再試行できる。

検証コピーと通常本棚接続は別ディレクトリを使用し、チェックポイントにもモードを記録する。モード不一致や破損時は上書きしない。通常本棚接続では画面内のコピー編集欄を出さず、通常画面で編集する。同期解除はチェックポイントだけを消し、既に通常本棚へ反映した整理情報を巻き戻さない。

## アダプターと保護

MacはShelfStore.changeを通常編集の入口に使い、受信時はlibrary.jsonへ原子的保存する。元のsources/path/bookmark、同じフォルダUUIDのiconFileを保持する。UUID資料IDは同期側で正規化し、Macの既知ID表記へ戻して資料との対応を維持する。初回反映前にlibrary.json.before-syncを一度だけ保存する。資料本体/画像/保存場所は同期しない。

iOSはCloudLibraryStoreの通常編集を使い、CloudFileStoreがorganization/classifications/collectionsを反映する。反映対象をtest-sync-apply.jsonへ原子的保存し、各JSON読込前に未完了の反映を回復する。旧3ファイルはbefore-test-sync.jsonへ一度だけバイト保存する。元のフォルダ画像参照を再結合し、保存済み資料・キャッシュ・非表示・認証を変更しない。反映後はPublishedの整理情報を更新して通常画面を再描画する。

## テスト起動

Macは別のCFBundleIdentifierを持つ検証ビルドに、両方の引数を渡す。実際のlibrary.jsonを指定せず、専用の合成JSONだけを指定する。

```sh
open -n '/path/to/Test Bookshelf.app' --args \
  --state /tmp/test-bookshelf/library.json --test-library-sync
```

iOSは新規作成した使い捨てSimulatorへテストビルドをインストールし、`simctl launch <使い捨てUDID> com.example.PresentationViewer --test-library-sync`で起動する。Simulatorかつサンプルモードの場合だけ有効。実機/本番API画面では引数があっても無効。

模擬サーバーは既存のscripts/organization-sync-http-check.pyの`--serve`を使い、画面へ表示された127.0.0.1のURLと同じライブラリUUIDを両方へ入力する。今回も外部ホスト/リダイレクトは拒否する。

## 確認した範囲

共通20、Mac25、iOS62テスト合格。通常保存から送信待ち/送信、受信反映、受信反映失敗後の再起動/再試行、競合解決、Mac固有参照保持、iOSの反映中断回復を合成データで確認。既存検証コピーの実loopback HTTPハーネスも合格。

専用画面操作ツールで、Mac通常画面のフォルダ作成→初回送信→サーバー保存後の応答喪失→再送→iOS通常フォルダ一覧への表示を確認。iOS通常画面で別フォルダ作成/資料選択/移動→送信→Mac通常フォルダ内に同じ資料を表示。さらにMac通常画面のタグ編集→送信→iOS通常タグ一覧へ表示。両端末は版5/送信待ち0/競合0で、保存済みフォルダ/所属/分類の一致を照合した。まとめの通常反映は自動テストで確認し、今回の実画面では操作していない。

Applications版/実機iPhoneへの更新、実データの移行・同期、AWS変更はなし。使い捨てSimulator・別IDのMacテストアプリ・合成本棚・模擬サーバーは削除/停止済み。証跡と制約は[作業記録](../sessions/2026-10-17-normal-library-sync.md)。本番接続へ進む前には初回バックアップの復元UI、利用者認証、実データ移行計画、長期オフライン/履歴保持の設計が必要。
