# AI資料生成の運用と責務

本基盤の中心はAIが資料を理解して構成を設計するための指示・ルール。数値・形式・保存・品質の正はAGENTS.mdから参照する各共通ルールに置く。

## 現行の制作経路

[作業経路](work-routes.md)で制作・アプリ改修・文書更新を分ける。制作では原資料の意味をAIが理解し、登録済みまたは制作パッケージ専用の契約へ渡す。対応状況は[CURRENT](../CURRENT.md)。

|対象|描画・保存の境界|
|---|---|
|通常プレゼン|登録v2、PNG/PDF/PPTX、一括制作。v1互換を保持|
|グラフィック版|共通6構図と画像台帳はschema1.3の登録経路。範囲外は専用固定登録と検証|
|独立一枚図|完成SVG/画像を専用CLIでPNG/PDFパッケージ化|
|旧定型単一図解|直列Roadmap JSONのSVG/PNG。全資料の必須入力にはしない|
|保存・閲覧|承認済み成果物を対応済み契約で非公開S3へ保存し、認証API/本棚へ提供|
|metadata-package 2.0|将来設計。登録プレゼンや独立一枚図の対応済み契約と区別|

## 選択条件
|依頼・構成|モードと手段|
|---|---|
|「この資料を図解して」、自然言語・Markdownから設計|Agent Creation Mode。資料読取・構成設計から始める|
|上記の構成が現行の直列Roadmapに適合|標準モード内でAIがJSONを作り、既存CLIで描画できる|
|分岐、境界、比較、並行段階、複数ページ、独自構成|プレゼンは登録v2または専用固定登録。一枚図はsvg/hybrid/image。意味を保てる経路を選ぶ|
|既存JSONから同一配置を再現、大量生成、回帰検証|Deterministic Rendering Mode。既存CLIを利用|
|明示的な決定的描画の依頼が既存範囲外|制約と代替案を提示し、モード変更を確認。意味を削って適合させない|

既存エンジンの正確な範囲はREADMEの「検証と制約」を参照する。テンプレートの意味規則とエンジンの実装範囲を混同しない。未指定の描画ツールは環境で利用できるものを選び、選択理由と未対応形式を記録する。

## 運用上の引き渡し
1. AI：原資料と読取範囲、入力整理票、要素ID、関係一覧、構成・配置設計を作る。
2. レンダラー：設計から描画ソースと画像を作る。既存エンジン以外では、その経路に必要な検査をAIが実施する。
3. エクスポート：同じ設計から選択経路の対応形式を生成し、形式間の内容・ID・関係・ページ順を照合する。
4. 品質検証：自動検査と目視確認を区別し、再レンダリング、修正、未検証事項を記録する。
5. 保存：rules/storage.mdに従いローカルに原資料参照・共通設計・描画ソース・成果物・検証記録を保持する。実施不能な検査を合格にしない。
6. S3・閲覧：既存仕様に適合する承認済み成果物だけ既存保存経路へ渡す。独自経路はローカル保存で完了できる。S3未対応を生成失敗と混同しない。

資料制作の依頼だけで新しいアプリ、クラウドリソース、自然言語解析CLIを追加しない。PDF・Word・PowerPoint読取や形式変換は実行環境に依存し、ツールを呼べたことと全文・全ページを正しく読めたことを区別する。

プレゼンの表現モード選択は[presentationプロンプト](../prompts/presentation.md)、グラフィック版の構成・イラスト・専用固定レイアウト・検証は[運用](presentation-graphic-mode.md)を参照する。表現モードと生成モードを混同しない。

新規図解の未指定サイズは[rules/layout](../rules/layout.md)の横長標準。説明不足は[rules/content](../rules/content.md)に従ってエージェントが補足し、原資料と根拠を区別する。CLIは完成した描画ソースを変換するため、既存成果物の寸法や本文を自動変更しない。
