# Mac/iOSのローカル同期検証画面

2026-10-17。[同期エンジン](organization-sync-local.md)を両アプリから利用する共通SwiftUIターゲットLibraryOrganizationUIを追加。今回は検証コピーだけを同期し、元の本棚へ受信結果を反映しない。通常の本棚画面での編集を自動送信する機能は未接続。AWS/API/認証/実機配布は変更しない。

## 入口と流れ

Macの上部「同期の検証」、iOSの右下ライブラリ→管理・設定→「同期の検証」。Source Storeのフォルダ/順序/所属/分類/タグ/まとめをURLのないOrganizationDocumentへ変換して取り込む。資料IDがUUIDの場合は大小文字を正規化し、それ以外の不透明IDは保持する。資料本体・保存場所・認証・画像ファイル名は送らない。

1. 模擬サーバーURLと両端末共通のライブラリUUIDを入力。IDの新規作成ボタンも利用できる。
2. 初回取込の競合はサーバー側/この端末を選び、全て確認してから送信待ちへ進める。初回確認までは端末情報を送らない。
3. 「今すぐ同期・再試行」で送信。状態/送信待ち/競合件数/最終同期/サーバー版を表示。
4. 検証コピー上でフォルダ追加/解除、資料移動/未整理、分類/タグ編集、まとめ作成/順序変更/解除を行う。元の本棚は変更しない。
5. 競合は双方の内容を表示し、サーバー採用/この端末を再送から選ぶ。削除先などinvalidの提案は再送不可とし、必要なら別の有効な編集を作る。
6. 通信失敗時は送信待ちを保持。接続先を修正して再試行できる。
7. 「検証コピーを解除」で端末のチェックポイントを削除し、空なら検証専用ディレクトリも削除。模擬サーバー側のデータは別なので、サーバー終了時に消去する。

Mac/iOSの通常設定へ自動適用しないため、取り込んだ資料や整理情報は常に残る。フォルダ画像や端末固有の参照も原本に維持される。未所持資料はID付きの未取得表示を用意する。検証コピーの編集/初回確認/同期前後を一つのcheckpoint.jsonへ原子的保存し、失敗時は前のチェックポイントから再送可能。破損したチェックポイントを黙って初期化/上書きしない。

## 接続と保存の制約

http://127.0.0.1だけを許可し、外部ホスト/本番URL/リダイレクトを拒否。実機iPhoneの127.0.0.1はMacではないため、今回の2クライアント検証はMacとiOS Simulatorを対象とする。実機へのLAN公開、トンネル、TLS例外、ATS設定変更は行わない。

Macはlibrary.jsonの隣のsync-lab/checkpoint.json、iOSは既存の利用者別保存領域内のsync-lab/checkpoint.jsonへ独立保存する。アカウント領域をまたいで同じファイルを共有しない。UI/セッションは@MainActorとbusyで直列化し、送信中の編集/解除を受理しない。通常の資料削除/キャッシュ清掃経路へ同期情報の保存処理を混ぜない。

## 再現

```sh
CLANG_MODULE_CACHE_PATH="$PWD/mac-app/.build/clang-cache" \
  swift test --disable-sandbox --package-path packages/LibraryOrganization \
  --cache-path "$PWD/mac-app/.build/cache"
python3 scripts/organization-sync-http-check.py \
  packages/LibraryOrganization/.build/debug/OrganizationSyncMock smoke-ui
```

自動ハーネスは2端末分の同じ画面セッションを合成資料で動かし、初回確認→送信→応答喪失→再送→同資料移動競合→再起動→解決→オフライン編集→再試行→削除→原データ不変→検証コピー解除まで検証する。サーバーと一時領域は自動終了/削除。

実画面確認用には末尾を `--serve` にすると空きポートのURLを表示して待機する。終了はCtrl-C。起動ごとに新しい一時領域を使う。固定の本番データへ接続する引数は用意しない。

## 今回の証跡

共有19件、Mac24件、iOS60件すべて合格。両アプリの取込アダプターテストで、元のフォルダ/タグ/まとめファイルのバイト不変を確認。実loopback HTTPで画面セッションと既存同期smokeが成功。

Mac実画面では初回確認、3件送信待ち、応答喪失による通信待ち、再試行→版3で同期済み、別端末を模したフォルダ編集との競合表示、サーバー採用で競合0件を確認。検証コピー解除後、元のlibrary.jsonは検証前とバイト単位で一致。元の65冊/フォルダ保持。検証ビルドを終了し、Applicationsの既存アプリへ戻した。

iOSも専用ツールで実操作を確認。隔離した新規Simulatorのサンプルモードで、同一IDフォルダの初回競合→端末案選択→送信待ち1件、接続拒否→通信待ちで1件保持→URL復旧→再送0件、別端末編集との競合→サーバー採用、再競合→端末案採用して再送→版5/送信待ち0/競合0まで成功。元organization.jsonは検証前後でバイト一致し、検証コピー解除後にcheckpointがないことも確認。実機配布・本番データ・AWS変更なし。

専用ツールのtimeoutReachedは、Simulatorアプリのプロセスだけを終了して同ツールから起動し直すことで復旧した。デバイスの起動やツール側セッション初期化だけでは復旧しなかった。CoreSimulatorの再起動・データ消去・権限変更は不要だった。原因の内部詳細までは断定できないが、アプリ側の接続状態に局在した可能性がある。再発時は検証デバイスの停止を確認し、Simulatorアプリの再起動後に専用ツールで画面取得を確認してから再開する。[成功した再検証](../sessions/2026-10-17-ios-sync-ui-validation.md)、[先行失敗の記録](../sessions/2026-10-17-ios-sync-ui-attempt.md)。

iOS証跡はmac-app/.build/validation/ios-sync-ui/のconflict.png、final-state.txt、data-check.txt。今回作成したSimulatorと模擬サーバーの一時データは削除済み。
