# 図解・プレゼンのフォルダ統合

2026-10-19本人依頼。Mac/iPhone/iPadの大項目を「図解」「プレゼン」に統一し、それぞれ独立したフォルダ一覧・作成・子フォルダ・移動・名前変更・解除を使う。図解の「まとめ」カードと作成入口を撤去し、従来のまとめは同じフォルダ一覧と移動先へ統合する。すべての資料一覧では、フォルダ所属によって資料カードを隠さない。未整理は通常所属も旧まとめ所属もない資料。

## 互換性と保存

共通`LibraryFolders.swift`が既存schemaVersion=1を維持して処理する。種類ごとの固定UUIDの親フォルダを内部に作り、大項目そのものはフォルダ操作の対象にしない。表示には親を除いた階層を使う。

以前の共有フォルダは名前・階層・並び順・画像参照を引き継いで2種類の独立したツリーに分ける。プレゼンは元UUIDを維持し、図解側はUUID先頭バイトの最上位bitを反転して決定的なUUIDを作る。既知の図解所属をコピー側へ引き継ぎ、未取得で種類不明の所属は元側に残す。種類が判明すると図解側へ解決する。両クライアントが同じ処理を使い、再実行で複製を増やさない。

従来のまとめはUUIDを引き継ぐ実フォルダを作る。既存の複数所属・読む順番・未取得資料のメタデータを失わないため、旧collectionsのスナップショットをフォルダ所属の補助情報として内部保持する。通常のフォルダ所属と合成して一覧を作る。別フォルダ/未整理への移動は補助所属を外して移動先へ所属させる。空になった補助情報は除去してもフォルダは残す。フォルダ解除は子孫の所属と対応する補助情報を外し、資料本体は保持する。旧順番はフォルダ内の初期表示順へ反映する。

読取時は共通の投影だけを行い、編集が成功したときに保存する。Macは管理JSON単位の原子的保存、iOSは既存の管理JSONジャーナルによる復旧を利用する。旧内部APIは互換性のため保持するが、新しい画面は統合経路を使用する。AWSコード・スキーマ・IAMの変更はない。

## 配布と検証

ローカル実装。端末への更新・本番の双方向同期・画面操作の確認は別途。旧アプリを混在させると、旧アプリには内部の親フォルダや旧まとめ表示が見えるため、実機反映時はMac/iPhone/iPadを揃える。

検証結果は[作業記録](../sessions/2026-10-19-folder-unification.md)を参照。

## 種類の入口と分類先の修正（2026-10-20）

iPadでは種類別の内部親を普通のフォルダとして出していたため、選択時に未整理を含まず、移動先名も空になっていた。種類の入口は「プレゼン（すべて）」「図解（すべて）」と表示し、所属なしを含む全資料を種類で表示する。実際の分類先はその配下の利用者フォルダだけとする。内部親への旧直接所属は未整理扱い、親への移動要求は未整理への移動として処理する。

Mac/iOSの移動メニューへ「新しいフォルダへ移動」を追加。iOSは新規フォルダ作成と選択IDの所属更新を同じ管理保存で実施し、再起動後も保持する。種類混在選択は種類別に分けて分類する。本人の既存フォルダ/所属を一括変更しない。[検証と配布](../sessions/2026-10-20-library-fetch-stability.md)。
