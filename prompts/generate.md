# 図解生成プロンプト

以下をコピーして値を記入する。未記入項目は未指定として扱う。

```text
このリポジトリのAGENTS.mdを入口として、必要な共通ルールと対応テンプレートを読み、図解を生成してください。

目的：<説明したいこと>
対象読者：<知識・利用場面>
希望タイプ：<Roadmap / Flowchart / Architecture / Comparison / 独自構成 / 自動判定>
表現モード：<通常モード / グラフィック版。未指定の新規制作では制作前に確認>
生成モード：<未指定ならAgent Creation Mode。定型再現が目的ならDeterministic Rendering Mode>
入力情報：<自然言語、Markdown、資料ファイルのパス、原文など。JSON必須ではない>
関係・条件：<接続、方向、分岐、前提。未知は未知と記載>
必ず含める情報：<項目一覧>
出典・対象版：<資料やURL、版>
出力形式：<任意。未指定時の対象はrules/export.mdの標準に従う。明示指定を優先>
サイズ・比率：<未指定ならrules/layout.mdの横長標準>
補足方針：<未指定ならrules/content.mdに従い不足する説明を補足。原文のみ等の指定を優先>
その他の明示条件：<任意>

図解の比率はrules/layout.mdの標準で統一し、PNGはrules/export.mdの標準寸法、PDFも同じ比率にしてください。「スマホ向け」だけでは比率を変更せず、横向き・拡大閲覧を想定してください。別の数値比率または寸法が明示された場合だけ変更してください。

プレゼン制作ではprompts/presentation.mdとdocs/presentation-graphic-mode.mdを読み、表現モードの指定がなければ通常モード／グラフィック版の選択を制作前に確認してください。選択済みなら再確認せず進めてください。
最初に入力整理票とタイプ判定を行い、結果を左右する不足情報は確認してください。情報量が不足する場合はrules/content.mdに従って用語・背景・具体例・注意点を補い、補足と根拠を記録してください。入力にない技術仕様や関係を原資料の事実として創作しないでください。
入力と図中要素の対応を記録し、共通の構成・配置設計から出力してください。資料を直接読み、読めない範囲を報告してください。生成モードと描画手段の選択理由を記録し、適合時は既存エンジン、範囲外ならSVG・HTML等を選んでください。どの手段でも共通デザインルールを適用してください。
rules/export.mdとrules/storage.mdに従い、図解ID・版単位の成果物パッケージ、形式別状態、整合性、不足分の再生成対象を記録してください。未対応形式を生成済みと扱わないでください。
ローカル保存を標準とし、S3は保存先と今回の資料送信の承認および既存仕様への適合を確認した場合だけ別工程で行ってください。
quality.mdとexport.mdに沿って検証・修正し、成果物と検証記録を提示してください。未検証項目と出力上の制約を明示してください。
```

プレゼンの枚数・密度は[rules/layout](../rules/layout.md)、基本配色と公式アイコンは[rules/design](../rules/design.md)に従う。明示された制作条件を優先する。
