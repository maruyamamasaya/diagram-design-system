# 図鑑 — Macの資料の本棚

macOS 14以降、SwiftUI/PDFKit/Quick Lookを利用するローカルアプリ。既存成果物を参照し、原本を移動・変更せずに整理する。iOS・AWS・同期は変更しない。ユーザーの明示的なMacアプリ制作依頼に基づく独立ターゲットで、生成エンジンの責務は維持する。

## 起動

```sh
mac-app/scripts/build-app.sh
open 'mac-app/dist/Zukan Bookshelf.app'
```

Finderで `dist/Zukan Bookshelf.app` を開いてもよい。「資料フォルダを登録」で既存の `outputs` を選ぶ。Appはローカル用のad-hoc署名。配布用署名・公証・App Store登録は対象外。外部依存なし。

## 操作

- 中央の表紙を選ぶと右にプレビュー。PDFはPDFKitのスクロール／ズーム、画像・PPTXはQuick Look。
- 同じ資料IDの各版は1冊に集約。右側で版や閲覧ファイルを選択。標準アプリ／Finderでも開ける。
- 検索はタイトルと資料ID。名前順／更新順、サムネイルサイズ変更に対応。本文全文検索は未実装。
- 左の「フォルダを作成」で分類。フォルダ選択中に作ると子フォルダになる。表示は階層パス。
- カードをフォルダにドラッグ、または右クリックの「フォルダへ移動」。親フォルダ選択時は配下も表示。
- フォルダを右クリックして名前変更／解除。解除した配下の資料は未整理へ戻る。原本は保持。
- 保存場所の登録解除も参照情報のみ削除。分類は資料IDに紐づけて保持し、再登録時に復帰する。
- ⌘Oで保存場所登録、⌘Rで再読込。登録フォルダ配下の変更は自動検知して反映する。

## 読込範囲

`metadata.json`を再帰探索し、標準プレゼン（presentationVersion・slides[].artifacts）、一枚図、独自制作パッケージの配列／辞書artifacts・filesを読む。タイトルがない場合はsource.json、PDF名、同IDの他版タイトルへフォールバックする。版は数値の降順。ページ数はmetadataの明示値・slides配列・PNG数の順。同一ID/版が複数場所にある場合はパス順で並び、版候補に各保存場所が残る。

宣言されたPDF/PPTX/PNG/JPEGを対象とし、assets/evidence/build/source/サムネイル等は本文候補から除外する。deliveryがあればその配下を優先。`outputs/パッケージ名/…`形式の旧参照もパッケージ内へ正規化する。シンボリックリンクの探索、パッケージ外参照を拒否。隠しディレクトリ・tests・*-tests・node_modules・build・evidenceは探索除外。読込失敗は「読込の注意」で表示し、部分的な取込成功を保つ。

今回の対象は既存のmetadata付き成果物。一般PDFだけのフォルダ、メタデータなしの制作中フォルダは取り込まない。完成判定は最低限のID/版/宣言ファイル存在と失敗状態の除外であり、制作品質やSHA256の再検証ではない。サムネイルは既存thumbnail.png、本文PNG、PDF表紙の順。PNGはImageIOで縮小する。

## 保存と共通化

設定は `~/Library/Application Support/ZukanBookshelf/library.json` に原子的に保存。アクセスブックマーク、保存場所、UUID付き階層フォルダ、資料ID→フォルダ割当を保持する。破損設定の自動上書きはしない。資料・索引の全件は起動／変更検知／アプリ再アクティブ化／手動更新時に再取得する。元ファイル消失時も分類設定を保持するが、資料カードはスキャン結果から外れる。

`BookshelfCore`はFoundationのみ。資料ID・版・フォルダ・設定保存・スキャナをUIから分離し、iOSへの導入に備える。iOSの既存collections/classificationsを移行する処理、同期、クラウド取込は未実装。Mac専用のsecurity-scoped bookmarkと表示はBookshelfターゲットに隔離する。

## 検証

```sh
BOOKSHELF_TEST_OUTPUTS="$PWD/outputs" CLANG_MODULE_CACHE_PATH="$PWD/mac-app/.build/clang-cache" \
  swift test --disable-sandbox --package-path mac-app --cache-path "$PWD/mac-app/.build/cache"
```

`--disable-sandbox`は制限された実行環境でSwiftPMが二重sandboxを起動できない問題へのビルド設定。アプリのOS保護設定は変更しない。本アプリ自体はApp Sandboxなしのローカル開発用ビルド。

テストは版集約／重複探索、標準・辞書形式、パス逸脱／欠落ファイル拒否、フォルダ保存復元／解除時の原本保持、実outputs読込。UI検証と件数はsessions/2026-10-17-mac-bookshelf.md参照。

## アプリアイコン

本棚のアイコンは`assets/Bookshelf.png`。`scripts/make-icon.swift`がAppKitの図形から16〜1024pxを描画し、`scripts/pack-icon.py`がICNSへ格納する。build-app.shでResources/Bookshelf.icnsとCFBundleIconFileを組み込むため、再ビルドでも維持する。

## 自動更新

Mac専用BookshelfWatchingがFSEventsで登録先を再帰監視。最終イベント後1秒待ってまとめて再読込し、連続書込中も最長5秒で確認する。監視は初回読込前に開始し、スキャン中のイベントは次のスキャンへ繰り越す。登録先が変わった場合のみ監視を差し替え、解除した保存先は監視終了する。非アクティブ中もアプリ起動中は監視し、再アクティブ化時にも再読込する。終了中の変更は次回起動で反映。監視開始失敗時は注意表示と30秒間隔の再読込に切り替える。

制作中のmetadataや宣言ファイルが揃わない資料は既存の取込検査で除外し、完成後の書込イベントで再評価する。制作側の完了品質を新たに保証するものではない。フォルダ/検索の選択や資料IDへの分類は維持する。元ファイルが削除された資料は一覧から外れるが、分類設定は残る。

監視の実OSテストはFSEventsにアクセスできる通常のMac環境で実行する。実行サンドボックスにより開始を拒否される場合、実OS接続の検証はその外で実施する必要がある。テストは一時ディレクトリ内の新規階層・新しい版・監視解除・保存先変更を確認する。

## 複数選択と一括移動

⌘クリックで選択の追加/解除、Shiftクリックで直前の基準カードから表示順の範囲選択。「すべて選択」は現在の検索・フォルダ内の資料を対象とする。下部の選択件数に対応した「○冊をフォルダへ移動」、または選択カードの右クリックから一括移動する。「未整理」で割当をまとめて解除できる。

選択は資料IDで保持するため版更新では維持する。検索・フォルダ変更や元資料の削除で一覧から外れたIDは選択解除。選択していないカードの右クリックはその1冊だけを対象にする。一括移動は設定ファイル1回の原子的保存で反映し、失敗時は元の設定を保持。元ファイルは移動しない。プレビューは最後に選んだ資料を表示する。

選択カードを左のフォルダ名へドラッグすると、選択した資料をまとめて移動する。「未整理」へのドラッグは選択した資料の分類をまとめて解除する。「未整理」自体は並べ替えの対象外。ドラッグ中は「○冊の資料」を表示し、受け取り可能なフォルダを強調する。クリックとドラッグはAppKitで区別し、選択したカードをつかんでも選択集合を維持する。選択外カードから始めた場合はその1冊だけを対象とする。ドロップはアプリ内のカード由来かつ既知の資料IDだけ受理し、キャンセルでは設定を変更しない。

Mac専用のCardDragSurface/FolderDropSurfaceが同一ウインドウ内の押下・移動・解放を処理し、解放位置のフォルダへ既存の一括保存処理で分類する。選択IDはドラッグ開始時に固定し、移動中は保存しない。対象外での解放・キャンセルは分類を変更しない。OSドラッグ受信は互換処理として残し、外部由来を拒否する。2026-10-17に配置済みアプリで2冊選択→一括ドラッグ、別の選択カードから別フォルダへ再移動、再起動後の保持を実画面確認。20件の回帰テストは実マウスハンドラーの複数ID・解放時保存・対象外・キャンセル・クリックも含む。

## フォルダごとの画像アイコン

左のフォルダを右クリックし「アイコン画像を設定…」で好きな画像を選ぶ。フォルダ選択後、上部のフォルダ設定メニューからも操作できる。「標準アイコンに戻す」で解除。PNG/JPEGなどOSのImageIOが読める画像に対応し、GIF等は先頭画像のみ。最大128pxに縦横比を保って縮小し、22pt枠で全体表示する（切り抜き編集なし）。

画像は設定ファイルと同じApplication Support領域のfolder-iconsへUUID名PNGとしてコピーする。元画像の移動/削除に依存しない。設定のiconFileは任意項目で、旧版のフォルダはそのまま読み込める。書込失敗時は以前の設定/画像を保持し、変更/解除に成功したときだけ以前のコピーを削除する。フォルダ解除時の孤立画像の一括清掃は未実装。画像の同期はしない。

## フォルダの並び替え

左のフォルダ名またはアイコンをつかみ、移動先のフォルダの上半分／下半分へドロップする。挿入線の位置に表示順を変更し、再起動後も維持する。表示順だけを変更し、フォルダの親子関係・画像・資料の所属は変えない。階層パス表示のまま、全フォルダを任意の順序へ配置できる。

最初の並べ替えまでは従来の名前/階層パス順を維持する。初回変更時にfolderOrderへUUID列を保存し、後から追加したフォルダは末尾へ表示。削除したフォルダIDは順序から除去する。フォルダの並べ替えは同一ウインドウ内のマウス移動/解放で直接処理し、資料のOSドラッグ（一括分類）と区別する。自己へのドロップ、外部由来/存在しないIDは拒否する。

Coreで上下移動・保存復元・旧設定・追加/削除・親子関係/資料/画像の保持を検証。2026-10-17の実画面確認で通常版の上下ドラッグを繰り返し、名前順とは異なる順序の再起動保持も確認した。フォルダ行は最低26ptを確保し、上下4ptの余白もドロップ位置として扱う。挿入線は解放/キャンセル後に除去。マウス押下→移動→解放とキャンセルも回帰テスト対象。

## 共通の整理パッケージ

フォルダ型・順序・移動/解除処理は`../packages/LibraryOrganization`を参照する。既存library.jsonの形は維持。iOS側の分類・タグ・まとめも同じパッケージの型を使用するが、画面・保存領域・同期は統合していない。[共通仕様](../docs/library-organization.md)。

## グループ・タグと図解のまとめ

資料を選び右の「タグを編集」、または右クリック「グループ・タグを編集」で仕事/私用/その他と自由タグを保存する。タグは1件ずつ追加/削除でき、未追加の入力も保存時に反映。空白/空タグ/大小文字だけ異なる重複を除く。原本メタデータのタグを初期値にし、端末の編集を全版に適用。「原本の分類に戻す」で上書きを解除。上部のグループ/タグをフォルダ・検索とANDで絞り込める。検索はタイトル/ID/タグ。

左の「まとめを作成」または複数選択後「選択からまとめ」で作成。iOSのルールに合わせPNG/PDFを持つ図解1〜100件、名前1〜120文字、同資料IDの重複なし。プレゼン資料はまとめの対象外。追加順を読む順とし、上へ/下へで編集。既存まとめは左側の右クリックやまとめ内の「編集」から変更できる。

すべての資料でグループ/タグの絞り込みなし・資料未選択ならまとめを1カード表示し、個別カードを隠す。まとめ名/含まれる資料名で検索できる。まとめを開くと読む順で個別資料を表示し、前/次の資料で右の既存プレビューを切り替える。フォルダや分類絞込中は個別資料として表示する。まとめ解除は設定だけで原本/フォルダ分類/タグを削除しない。

library.jsonのschemaVersion=1を維持し、任意追加classifications/collectionsを旧ファイルから空として読込。資料ID単位で保持し、更新で最新版へ解決。まとめにはURLを含まないスナップショットを残すため、原本一時消失でも所属と順序を失わず、未取得件数を表示する。分類編集・まとめ保存は原子的に書き、失敗時は編集画面と元の設定を保持。

iOSと共通の型/正規化/構造検証を使うが、同期・クラウド・iOSデータ取込は追加しない。Macのまとめ閲覧は資料単位の切替であり、複数資料のPNGを一つのページ列にするiOS専用閲覧とは異なる。metadataのschema/識別キーから図解とプレゼンを判別する。既存の判別できない独自パッケージはプレゼン扱い。

## ローカル同期の検証

上部「同期の検証」から模擬サーバーURL/共通ライブラリIDを指定し、初回統合・送信待ち・競合の採用・再試行を確認できる。元の本棚とは別の検証コピーだけを同期する。通常画面の編集の自動送信や、元設定への受信反映は行わない。[使い方・片付け](../docs/organization-sync-ui.md)。

明示テスト起動で通常本棚を接続する場合は[通常本棚](../docs/organization-sync-bound.md)と[合計5回/時・追加確認](../docs/organization-sync-quota.md)を使用する。上限中の編集は送信待ちに保存し、バックアップ復元/切断で回数を初期化しない。

## 通常本棚の認証付き整理同期

`config/organization-sync.json`の公開設定をInfo.plistへ組み込むビルドでは、本人ログイン後に通常本棚の整理情報を同期できる。初回は管理JSONの自動バックアップと統合件数を確認してから送信する。資料本体・画像は送信しない。同期は画面から手動実行し、全端末合計5回/時。以前の「同期を追加しない」は各機能を実装した時点の範囲。[現在の接続状況と復元](../docs/organization-sync-live-clients.md)。
